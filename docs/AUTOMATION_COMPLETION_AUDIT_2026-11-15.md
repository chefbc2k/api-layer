## Finite stopping rules

For remaining build jobs, freeze named acceptance IDs/method keys and the mounted deployment inventory, use one owner per item, record accepted evidence and delivered commit, and pause the job when no accepted-scope item remains open. When only external prerequisites remain, put the job into an explicit blocked/waiting state and resume on a changed prerequisite instead of regenerating unchanged reports. This is a recommendation; remaining automation prompts were preserved.

For Paperclip, complete a finite project only after its deliverables and cross-project dependencies pass acceptance; explicitly reconcile project status. For recurring operational services, define either an intentional ongoing owner/cadence or a fixed campaign end/KPI. Add a routine dispatch condition that suppresses new execution issues while the canonical dependency is unresolved, and a terminal project/campaign condition that disables its trigger. Empty boards, error states, and completed planning documents are insufficient release evidence.
